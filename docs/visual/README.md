# V4 component render evidence

Generated by `flutter test test/v4_visual_test.dart --dart-define=V4_CAPTURE=true` on Windows. PNG files are actual Flutter widget-test renders of the existing phone field, calendar and floating navigation, using explicitly labelled test fixtures. They are not Android screenshots, API integration evidence, full-screen acceptance, or goldens compared against the approved wireframe.

| File | Logical viewport | Text scale |

| `v4-components-390.png` | 390 x 1000 | 1.0 |
| `v4-components-430.png` | 430 x 1000 | 1.0 |

Regenerated and all three images opened/reviewed for the 2 November booking-success addendum. Calendar status colours remain visible with a blue selected outline, and the badge overlaps the upper-right Bell glyph. Navigation is fully icon-only, with an elevated blue Compass; full tab labels remain in semantics and tooltips. At 320/1.8, weekday labels wrap. Badge numerals do not scale, keeping the Bell visible while its semantics announce the full unread count. Content scrolls independently of navigation.

Rendering limitations: these captures use Windows Arial and the application's MaterialIcons font, not the production Plus Jakarta Sans font. Windows test rendering has no regional-flag font, so the flag appears as missing glyphs. Country flag appearance, platform font fallback, system bars, keyboard and route transitions require Android verification. No font files were copied into the repository.

Normal test execution loads the SDK's bundled Roboto font to avoid Ahem's intentionally wide test glyphs. The SDK font path is derived from `flutter_tester`, and screenshot capture is opt-in so the normal suite does not rewrite evidence.
